# CP-02 — Per-Cluster Feature Profile & Behavioural Analysis

> **Task ID:** EPIC-09 / CP-02

## 1. Objective

Trả lời các câu hỏi về **đặc trưng và hành vi** của customer segments
do EPIC-07 + EPIC-08 sản xuất:

1. Mỗi cluster có đặc điểm feature như thế nào?
2. Giá trị trung tâm / phân bố của các feature trong từng cluster ra sao?
3. Các cluster khác nhau tương đối như thế nào?
4. Có thể mô tả hành vi của cluster dựa trên các feature nào?

CP-02 chỉ báo cáo **đặc trưng và hành vi mô tả** (descriptive only).
CP-02 không đặt tên segment, không suy diễn feature nào "phân biệt cluster
mạnh nhất" (CP-03), không marketing recommendation (CP-05), không đánh
giá algorithm nào tốt nhất (AGENTS.md §2.5; EPIC-08 boundary).

## 2. Scope

### 2.1 In scope

- Per-(cluster, feature) statistics trên RAW interpretable values:
  count, count_total, mean, median, P25, P75, min, max, std,
  n_missing.
- Relative comparison: cluster statistic vs OVERALL (non-noise)
  population statistic (median-based).
- Behavioural interpretation per (cluster, feature) với ngôn ngữ
  "cao hơn tương đối" / "thấp hơn tương đối" / "gần tương đương" dựa
  trên relative difference vs OVERALL.
- Visualisation: boxplot per (cluster, feature) cho RFM + behavioural
  + cancellation subset (7 features) và heatmap 14-feature × n_clusters
  của relative % vs OVERALL median (signed, centered at 0).
- CP-01 ↔ CP-02 consistency check (cluster customer counts).

### 2.2 Out of scope (deferred to CP-03 → CP-05)

- Feature nào phân biệt cluster mạnh nhất → CP-03.
- Cluster nào nên đặt tên gì → CP-04.
- Segment nên Marketing như thế nào → CP-05.
- Algorithm nào tốt nhất / cluster nào "quan trọng nhất".
- Business recommendation.

### 2.3 Algorithm / methodology scope (locked)

- Năm thuật toán benchmark cố định (per ADR-0003): K-Means,
  Agglomerative, DBSCAN, GMM, Fuzzy C-Means. **K-Medoids OUT OF
  SCOPE** — không xuất hiện trong CP-02 outputs.
- Two conditions: EXP-01 working-default + EXP-03 working-selected.
- Total: 10 analysis units, identical to CP-01.
- RAW interpretable features từ FE-05 output (KHÔNG dùng
  Yeo-Johnson + RobustScaler values từ FE-06 — transformation không
  trực tiếp map về business units).

## 4. Analysis Method

### 4.1 Package location

`src/customer_segmentation/profiling/cp02/`:

- `provenance.py` — Loads RAW features + cluster labels, joins by
  CustomerID, builds Cp02AnalysisUnit per (algorithm × condition).
- `feature_profiling.py` — Per-(cluster, feature) statistics on
  RAW values.
- `relative_comparison.py` — Relative difference vs OVERALL
  population (median-based).
- `behavioral_interpretation.py` — Directional interpretation per
  (cluster, feature) using feature-specific semantics.
- `visualization.py` — Boxplots + relative heatmaps.
- `report.py` — Markdown report builder.
- `runner.py` — Top-level orchestration (`run_cp02()`,
  `Cp02Runner`).

### 4.2 Statistics computed per (cluster, feature)

For each cluster (excluding DBSCAN noise), for each of the 14 features:

- ``count`` — số khách hàng có giá trị non-NaN.
- ``count_total`` — tổng khách hàng trong cluster (bao gồm NaN).
- ``mean``, ``median``, ``P25``, ``P75``, ``min``, ``max``, ``std``
  (NaN được loại trừ khỏi tính toán; không silent impute).
- ``n_missing`` — số khách hàng có NaN cho feature trong cluster.

Cùng statistics cũng được tính cho OVERALL (non-noise subset của
analysis unit) làm reference cho relative comparison.

### 4.3 Relative comparison

Công thức:

```
relative_difference_pct = (cluster_value - overall_value) / |overall_value| × 100
```

`overall_value` = OVERALL (non-noise) population statistic cho cùng
analysis unit, cùng feature.

- Reference = median (primary; robust với heavy skew / outliers).
- Mean-based relative difference cũng được tính và lưu trong
  ``rel_diff_mean_pct`` column.

Division-by-zero / unsuitability:
- Nếu `|overall_value| ≤ 1e-9` → `reference_status = "ZERO_REFERENCE"`,
  `rel_diff_pct = NaN`. Áp dụng cho các feature có thể = 0 cho
  phần lớn customers (ví dụ `CancellationRate`).
- Nếu cluster_value HOẶC overall_value là NaN →
  `reference_status = "NA"`, `rel_diff_pct = NaN`.
- Ngược lại → `reference_status = "OK"`.

### 4.4 Behavioural interpretation thresholds

Direction thresholds (analytical defaults; **KHÔNG phải research-grade**):

| Direction | Condition |
|---|---|
| `HIGHER` | `rel_diff_median_pct ≥ +10%` |
| `LOWER` | `rel_diff_median_pct ≤ -10%` |
| `COMPARABLE` | `-10% < rel_diff_median_pct < +10%` |
| `ZERO_REFERENCE` | `overall_value ≈ 0` |
| `NA` | `NaN` in either cluster_value or overall_value |

Người đọc có thể thay đổi thresholds (HIGH_THRESHOLD_PCT /
LOW_THRESHOLD_PCT) và re-bin direction.

### 4.5 Feature semantics

Mỗi feature có hành vi semantic riêng. Ví dụ:

- `Recency` (INVERTED): giá trị thấp hơn = lần mua gần đây hơn →
  "cluster có Recency thấp hơn tương đối" = "quan sát thấy lần mua
  gần đây hơn population".
- `Frequency` (giá trị cao hơn = nhiều hóa đơn hơn) → "giao dịch
  thường xuyên hơn tương đối".
- `Monetary` (giá trị cao hơn = chi tiêu cao hơn, RAW value tính bằng
  GBP) → "chi tiêu quan sát được cao hơn tương đối".
- `CancellationRate` / `ReturnRate`: redundant theo FE-06
  (Pearson = 1.0); CP-02 vẫn báo cáo cả hai để đảm bảo 14-feature
  surface đầy đủ.

`FEATURE_SEMANTICS` (mapping feature → Vietnamese sentence) được embed
trong module `behavioral_interpretation.py`. Mỗi feature có 3 phần
text: `high` (cao hơn), `low` (thấp hơn), `neutral` (gần tương đương).

### 4.6 Noise handling

- DBSCAN `ClusterLabel == -1` được tách riêng trong CP-01 size table.
- CP-02 KHÔNG profile noise như Customer Segment.
- ``eligible`` subset (cluster ≠ -1) là denominator cho OVERALL
  statistics — nhất quán với CP-01 `pct_of_assigned`.

### 4.7 Runner

`scripts/run_cp02.py` — single entry-point:

```
python3 scripts/run_cp02.py [--output-dir PATH] [--no-exp03]
```

### 7.2 Standardised profile heatmap

`reports/profiling/cp02/figures/cp02_*_heatmap.png`:

- One per analysis unit (5 heatmaps).
- Rows = clusters; columns = 14 features.
- Cell value = signed percentage difference (cluster median vs
  OVERALL median).
- Colour scale: diverging (RdBu_r), centred at 0, capped at the 98th
  percentile of |values| to keep the scale robust to extreme outliers.
- Warm colours = `HIGHER`, cool colours = `LOWER`.
- Caption explicitly marks the chart as **"Standardised profile
  heatmap (relative % vs overall median)"** — KHÔNG phải business-
  value chart.

### 7.3 Why the heatmap is a "standardised profile heatmap"

The heatmap colours represent **signed relative % vs OVERALL median**,
NOT business values. A reader cannot read this chart as "Monetary
of Cluster X is 200 GBP". To get business values, the reader must
consult the `cp02_feature_profile_table.csv` (median column).

## 9. Findings

CP-02 phân tích trên cùng dataset CP-01 (FE06-v1.0 / RFM Extended /
4,371 customers × 14 features / EXP-01 working-default) cho thấy:

### 9.1 Per algorithm — descriptive observations

#### K-Means (K=4)

- C0 (n = 555): cluster có **TenureDays cao hơn tương đối** (+157%) +
  **ActiveDays cao hơn tương đối** (+100%) + **Recency thấp hơn
  tương đối** (-35%). Mô tả: cluster có thời gian quan hệ dài và lần
  mua gần đây hơn population.
- C1 (n = 3,021, dominant): cluster có **Recency cao hơn tương đối**
  (+27.5%) + **TenureDays thấp hơn tương đối** (-88.8%) +
  **Frequency thấp hơn tương đối** (-33.3%) + **Monetary thấp hơn
  tương đối** (-33.3%). Mô tả: cluster có thời gian quan hệ ngắn và
  ít giao dịch hơn population.
- C2 (n = 571): cluster có **TotalQuantity cao hơn tương đối** (+230%)
  + **Monetary cao hơn tương đối** (+219%) + **ActiveDays cao hơn
  tương đối** (+200%) + **Recency thấp hơn tương đối** (-70.6%) +
  **PurchaseIntervalMean/Std thấp hơn tương đối** (-63% / -66%). Mô
  tả: cluster có chi tiêu cao hơn population và cadence ổn định hơn.
- C3 (n = 224): cluster có **PurchaseIntervalStd cao hơn tương đối**
  (+269%) + **TenureDays cao hơn tương đối** (+193%) + **Recency thấp
  hơn tương đối** (-55%). Mô tả: cluster có cadence thay đổi nhiều
  nhưng thời gian quan hệ dài.

> KHÔNG có tên segment, KHÔNG ranking giữa các cluster.

#### Agglomerative (K=4)

Direction profile tương tự K-Means (cùng input matrix, cùng K=4).
Cluster sizes khác nhau ở rìa (smallest = 155 vs K-Means 224).

#### DBSCAN (K_realized=17)

17 non-noise clusters + 1 noise bucket (3,177 customers = 72.68%).

- Cluster 1 (n = 1,042, dominant non-noise): direction profile tương
  tự K-Means C1 (Recency cao hơn tương đối, TenureDays thấp hơn
  tương đối).
- 16 clusters còn lại có n ≤ 37; n_missing phổ biến cho
  PurchaseIntervalMean/Std (đa số single-invoice customers).
- Các cluster rất nhỏ (n ≤ 10) có std NaN — không ước lượng được.

#### GMM (K=4)

Direction profile tương tự K-Means + Agglomerative với sự khác biệt
ở cluster sizes (GMM phân bố cân bằng hơn theo CP-01 distribution
indicators).

#### Fuzzy C-Means (K=4)

- C0 (n = 1,337): HIGHER ActiveDays (+200%), LOWER Recency (-71%).
- C1 (n = 529): HIGHER TenureDays (+192%), PurchaseIntervalStd
  (+269%).
- C2 (n = 1,928, dominant): HIGHER Recency (+28%), LOWER TenureDays
  (-89%), Frequency (-33%).
- C3 (n = 577): phần lớn features ở trạng thái COMPARABLE.

### 9.2 Cross-algorithm observations

CP-02 KHÔNG so sánh clusters across algorithms. Mỗi analysis unit
được báo cáo độc lập. Cross-algorithm comparison là CP-04 territory
(không thuộc CP-02 scope).

### 9.3 Feature-specific patterns (mô tả)

- **Recency** — phân tách cluster "mua gần đây" vs "mua từ lâu" tốt
  nhất trong các fixed-K algorithms. Tất cả 5 algorithms đều có ít
  nhất một cluster với Recency thấp hơn tương đối và một cluster với
  Recency cao hơn tương đối.
- **TenureDays** — phân tách cluster "quan hệ dài" vs "quan hệ ngắn".
- **Monetary + Frequency** — thường đi cùng nhau (clusters có
  Monetary cao cũng có Frequency cao).
- **CancellationRate / ReturnRate** — phân bố rất skewed về 0 trong
  dataset hiện tại (cancellation rate rất thấp cho đa số customers);
  nhiều cluster có `rel_diff_pct` ở `ZERO_REFERENCE` hoặc trong band
  COMPARABLE.
