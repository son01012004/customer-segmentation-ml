# CP-01 — Phân tích quy mô và phân bố Customer Segments

> **Task ID:** EPIC-09 / CP-01
> **Status:** IMPLEMENTED + VERIFIED (31 unit tests pass)
> **Generated:** 2026-09-23

## 1. Objective

Trả lời các câu hỏi về **quy mô, tỷ lệ, phân bố và relative size** của
customer segments do EPIC-07 + EPIC-08 sản xuất:

1. Có bao nhiêu customer trong mỗi cluster?
2. Mỗi cluster chiếm bao nhiêu phần trăm?
3. Quy mô tương đối giữa các cluster như thế nào?
4. Distribution có cân bằng hay không?
5. Có cluster quá nhỏ / quá lớn / bất thường về quy mô không?

CP-01 chỉ báo cáo **size / proportion / distribution**. CP-01 không
đặt tên segment, không so sánh thuật toán, không marketing
recommendation, không dùng quality metrics thay cho size analysis.

## 2. Scope

### 2.1 In scope

- Per-cluster counts và percentages cho mỗi analysis unit
  (algorithm × condition).
- Relative size ratio (cluster count / largest segment count).
- Distribution indicators (largest, smallest, ratio, range,
  deviation-from-equal-size, median).
- DBSCAN noise separation (label = -1) riêng biệt với customer segments.
- Bar-chart visualisation cho mỗi analysis unit.

### 2.2 Out of scope (deferred to CP-02 → CP-05 hoặc future work)

- Cluster đặt tên ("Champions", "VIP", ...)
- Customer-value / behaviour analysis
- Marketing / campaign recommendation
- Algorithm comparison / ranking (AGENTS.md §2.5; pending
  `EPIC08-CROSS-ALG-01`)
- `WORKING_SELECTED` → `BEST / OPTIMAL` promotion

### 2.3 Algorithm / methodology scope (locked)

Five algorithms only (per ADR-0003): K-Means, Agglomerative, DBSCAN,
GMM, Fuzzy C-Means. **K-Medoids OUT OF SCOPE** — không xuất hiện trong
CP-01 outputs.

## 4. Analysis Method

### 4.1 Package location

`src/customer_segmentation/profiling/cp01/`:

- `provenance.py` — Resolution of analysis units from source artifacts.
- `size_analysis.py` — Per-(unit, cluster) counts + percentages.
- `distribution.py` — Distribution indicators (largest, smallest,
  ratio, range, deviation, median).
- `visualization.py` — Bar charts (count + percent).
- `report.py` — Markdown report builder.
- `runner.py` — Top-level orchestration (`run_cp01()`,
  `Cp01Runner`).

### 4.2 Denominator policy

- ``pct_of_assigned`` — share among **non-noise** customers.
  Used for cross-cluster comparison within one segmenting.
- ``pct_of_total`` — share among **all** customers in the unit
  (noise is in denominator for DBSCAN).

These two denominators are recorded explicitly in each row so a reader
knows which denominator applies.

### 4.3 Distribution indicators

| Indicator | Definition | Source |
|---|---|---|
| `n_clusters` | number of non-noise segments | computed |
| `largest_cluster_count` | max(segment_counts) | computed |
| `smallest_cluster_count` | min(segment_counts) | computed |
| `largest_pct_of_total` | largest / total × 100 | computed |
| `largest_to_smallest_ratio` | largest / smallest | computed |
| `size_range` | largest − smallest | computed |
| `deviation_from_equal_size` | mean(\|size − n_total / n_clusters\|) | computed |
| `median_cluster_size` | median of segment sizes | computed |

### 4.4 Noise handling

- DBSCAN `ClusterLabel == -1` is treated as noise and reported in a
  separate `cp01_noise_summary.csv` row.
- Noise is **NOT** counted as a customer segment.
- Noise bars in charts use a distinct hatch (`///`) and a separate
  legend entry so a reader cannot mistake it for a segment.

### 4.5 Runner

`scripts/run_cp01.py` — single entry-point:

```
python3 scripts/run_cp01.py [--output-dir PATH] [--no-exp03]
```

## 6. Distribution Analysis

Key observations, per algorithm, **descriptive only**:

### 6.1 K-Means (EXP-01, K=4)

- 1 segment lớn (3021 customers = 69.11% of 4,371)
- 3 segments còn lại nhỏ (224 / 555 / 571, tổng 31.89%)
- `size_range` = 2797; `deviation_from_equal_size` = 964 (≈ 4× n_total / K)
- Có thể mô tả là "skewed toward a single dominant segment" (mô tả,
  KHÔNG kết luận tên / giá trị).

### 6.2 Agglomerative (EXP-01, K=4)

- 1 segment lớn nhất (3040 = 69.55%); 1 segment nhỏ nhất (155 = 3.55%).
- Distribution khá giống K-Means về hình dạng, nhưng smallest segment
  nhỏ hơn (largest_to_smallest_ratio = 19.61).
- Mô tả: "skewed, smallest segment < 4%".

### 6.3 DBSCAN (EXP-01, eps=0.5, min_samples=5)

- 17 non-noise clusters + 1 noise bucket (3177 customers = 72.68%).
- 1 cluster dominant (1042 customers = 87.27% of the **non-noise**
  subset).
- 14 of 17 clusters có ≤ 10 customers; 5 clusters có ≤ 5 customers.
- `size_range` (non-noise) = 1039; `deviation_from_equal_size` ≈ 114
  (rất thấp vì abs deviation so với equal 1194/17 ≈ 70 rất nhỏ trên
  các cluster nhỏ nhưng lại lớn trên cluster 1042; giá trị tuyệt đối 114
  trên quy mô 1194).
- Mô tả: "DBSCAN noise bucket riêng biệt, phân bố segments rất
  imbalanced trong nhóm non-noise, nhưng KHÔNG nói được ngụ ý tên /
  giá trị segment".

### 6.4 GMM (EXP-01, K=4)

- 2 segments lớn (~ 47% + ~ 25%); 2 segments nhỏ (~ 22% + ~ 6%).
- `deviation_from_equal_size` = 489 (thấp nhất trong 4 fixed-K algos).
- Mô tả: "less skewed than K-Means / Agglomerative".

### 6.5 Fuzzy C-Means (EXP-01, K=4)

- Cân bằng nhất trong 4 fixed-K algos:
  `largest_to_smallest_ratio` = 3.64 (vs K-Means 13.49, Agg 19.61,
  GMM 8.11).
- `deviation_from_equal_size` = 540 (so với K-Means 964).
- Mô tả: "smallest/largest ratio thấp nhất trong các fixed-K algorithm".

> KHÔNG algorithm nào được gọi là "best". Mỗi algorithm được mô tả
> riêng; bạn đọc tự quyết định "imbalance" có ý nghĩa gì theo research
> question của mình.

## 9. Findings

The cluster-size distribution under EXP-01 working-default
(`final_clustering_dataset.parquet` × RFM Extended × C7 preprocessing ×
4371 customers) shows the following descriptive patterns:

- Across the 4 fixed-K algorithms (K=4), there is always one segment
  with the largest customer count. Across algorithms, that "largest"
  segment occupies 44.11% (FCM) to 69.55% (Agglomerative) of the total.
- Across the 4 fixed-K algorithms, the smallest non-noise segment
  ranges from 155 customers (3.55%, Agglomerative) to 529 customers
  (12.10%, FCM).
- The distribution skew differs by algorithm (FCM has the lowest
  largest-to-smallest ratio among fixed-K algorithms; Agglomerative
  has the highest). No algorithm is described as "best" or "most
  imbalanced".
- DBSCAN produces 17 realised clusters + a noise bucket of 3177
  customers (72.68% of total). The noise bucket is reported
  separately and is NOT a customer segment.

## 11. Research Boundary

CP-01 conclusions are bounded to:

- FE06-v1.0 (RFM Extended feature set, 4,371 customers, 14 features)
- EXP-01 working defaults (K=4 for kmeans / agglomerative / gmm / fcm;
  realised K=17 for DBSCAN)
- 5 algorithms only (K-Medoids OUT OF SCOPE per ADR-0003)
- The UCI Online Retail dataset
- The CP-01 code is read-only against EXP-01/EXP-03 artifacts.

CP-01 does NOT extrapolate to:

- All retail datasets
- All customer-segmentation problems
- All preprocessing strategies
- All business contexts
- Marketing recommendations
- Cluster naming or value attribution
- Algorithm ranking / quality judgement
